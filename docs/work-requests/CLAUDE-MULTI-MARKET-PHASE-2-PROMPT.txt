MM2-03  Pipelines have no pack-ownership column.               SEVERITY: MEDIUM
        Owner: backend/prisma/schema.prisma (this phase may not edit it)
--------------------------------------------------------------------------------
TaxonomyTerm, AttributeDefinition and FieldPolicy each carry `packCode`, so
provisioning can tell its own rows from the tenant's. Pipeline and PipelineStage
do not — and they are the rows that MUST converge when a tenant changes
industry, because every pack ships the same pipeline code and the same three
stage codes and differs only in wording.

Claude's workaround records what the pack last wrote in
`Organisation.settings.packManaged` (backend/src/config/industry-packs/
pack-managed.ts) and treats a row that still matches that record as pack-owned.
It works, it is explicit rather than a name/code guess, and it is tested — but it
keeps ownership in a JSON bag instead of beside the row it describes.

Requested, when the schema is next open: `packCode String?` on Pipeline and
PipelineStage, after which the settings record can be deleted and the comparison
becomes a column read.


--------------------------------------------------------------------------------
MM2-04  ensureDefault can permanently pre-empt the pack funnel. SEVERITY: MEDIUM
        Owner: backend/src/crm/pipelines.service.ts
--------------------------------------------------------------------------------
`PipelinesService.ensureDefault` creates a pipeline with `code: 'default'` named
"Sales pipeline", with stage codes inquiry/quotation/order_placed — the same key
the industry pack uses.

If `POST /crm/pipelines/ensure-default` runs before a pack is applied, the pack's
pipeline is skipped for ever (provisioning finds `default` already present), and
Claude's convergence cannot help either: there is no ownership record, so those
stages are correctly treated as the tenant's and left alone. The tenant is left
on generic English whatever industry they pick.

Requested: have `ensureDefault` defer to the organisation's pack when one is
applied, or stamp the rows it creates so provisioning can recognise and replace
them. Claude may not edit that file in this phase (crm/** is allowed only for
atomic settings updates and existing vocabulary).
