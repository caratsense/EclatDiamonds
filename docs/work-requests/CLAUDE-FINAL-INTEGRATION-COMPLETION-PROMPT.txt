WAVE 3 — SPEND, ROAS AND PROVIDER TRUTH
===============================================================================

INT-05 — REMOVE MEASURED META SPEND FROM LEGACYROW

- LegacyRow is the ERP mirror and is writable through generic sync. It cannot be
  the authoritative Meta spend ledger.
- Add the smallest dedicated additive model(s), for example MetaAdSpendDaily and
  MetaAdSpendCoverage, with organisationId, integrationId, adAccountAssetId,
  date, account/campaign/ad-set/ad identifiers, amount, currency, source update
  time, fetch/run provenance and idempotent unique keys.
- Enforce tenant relations and useful date/account/campaign indexes.
- Migrate existing valid Meta spend/coverage LegacyRows into the dedicated model
  idempotently; do not copy malformed or unprovable rows.
- Update ingestion and reports to use only the dedicated measured-spend source.
- Ensure ERP/Connect sync cannot write these tables.

INT-06 — MAKE CURRENCY CORRECTNESS EXPLICIT

- Read the Meta ad-account currency and the organisation/sale currency.
- MVP rule: calculate ROAS only when currencies match. For a mismatch, return
  available=false with both currency codes and reason=currency_mismatch.
- Do not silently convert and do not assume INR.
- If a dated FX provider is already genuinely implemented, conversion may be
  added only with rate source/date/currency provenance and tests. Otherwise keep
  the safe equality gate.
- Keep declared campaign budget/spend separate from measured provider spend.
- Partial date/account coverage must return unavailable/incomplete, not a number.

INT-07 — PROVIDER HEALTH AND ASSET OWNERSHIP CHECKS

- Store bounded error codes/messages, never tokens or raw Graph responses.
- Distinguish not_configured, configured, connected, needs_attention and disabled.

INT-08 — META TEMPLATE SYNCHRONISATION
