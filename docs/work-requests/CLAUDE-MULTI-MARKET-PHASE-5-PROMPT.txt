MM4-02  Docker backend target. NOW AN EXPLICIT BUILD INPUT.
        frontend/Dockerfile — `ARG BACKEND_ORIGIN` + `ENV BACKEND_ORIGIN=
        $BACKEND_ORIGIN` before `RUN npm run build`, no default, plus a guard
        that FAILS THE BUILD when the arg is absent.
        The guard is not belt-and-braces, it is the fix. An unset ARG expands to
        the EMPTY STRING and ENV sets it anyway, so next.config.ts's
        `process.env.BACKEND_ORIGIN ?? "<production>"` never falls back: an
        image built without the arg would rewrite /_api to itself and 404 every
        API call at runtime. The first version of this change shipped a comment
        claiming the production origin would be inherited — wrong, and caught by
        the review's completeness critic. Comment and tests now describe the
        real mechanism.
